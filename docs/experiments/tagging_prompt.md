- 날짜: 2026-10-26
- 모델: `gpt-5.4-mini-2026-03-17` (구조화 출력 + Pydantic 검증)
- 기준선: 키워드 베이스라인 (`track1_tagging/keyword.py`)
- 비교 지표: (1) 키워드와 LLM의 확정 태그(confidence 0.6↑) 일치율, (2) B가 라벨링한 `data/labels/sample50.csv` 기준 정밀도·재현율·F1 (`scripts/evaluate_tagging.py`)
- 실행: `uv run python scripts/run_tagging.py --method all [--sample 50] --prompt v3`

## 1. 샘플 50건 프롬프트 실험 (가게 30 · 자원 20)

| 프롬프트 | F01 | F02 | F03 | F04 | 불일치 | 입력/출력 토큰 |
|---|---|---|---|---|---|---|
| v1 | 84% | 88% | 88% | 98% | 21건 | 37,701 / 5,059 |
| v2 | 84% | 92% | 96% | 98% | 15건 | 53,051 / 4,832 |
| v3 | 88% | 92% | 98% | 98% | 12건 | 63,501 / 4,992 |

**v1 → v2**: 불일치를 직접 보니 LLM이 과신하는 패턴이 있었다.
- 작은 슈퍼마다 F03(무거운 상품)을 0.65 이상 → 근거 없으면 0.4~0.5(확인 필요)로 두도록 업종별 기준 추가
- 닭집에 F01·F03 → 정육·수산은 F02만
- "확실하지 않으면 0.6 미만" 원칙 추가 (담당자 확인 단계가 있으므로 과신보다 확인 필요가 낫다)

**v2 → v3**: 규칙을 넣어도 고쳐지지 않은 두 가지를 실제 이름 예시로 보강했다.
- 고속도로 휴게소 편의점에 F01 0.95 → "○○휴게소점"은 기능 없음
- 치즈 특산물 판매장에 F01 → 주민 생필품 구매처 아님

v3에서 남은 불일치 12건은 대부분 0.5~0.6 경계값이거나 사람이 봐도 갈리는 경우였다. 다이소(F01), 곡물 농장(F03)은 키워드 규칙이 놓치고 LLM이 맞힌 경우다.

## 2. 전체 실행 (영업 가게 152 · 자원 368, 프롬프트 v3)

- 새 호출 470회 (샘플 50건은 캐시 재사용), 입력 592,413 / 출력 38,799 토큰, 79초 (병렬 8)

| 기능 | 일치율 | 키워드만 확정 | LLM만 확정 | 둘 다 확정 |
|---|---|---|---|---|
| F01 생필품 | 94.8% | 18 | 9 | 85 |
| F02 신선식품 | 95.0% | 11 | 15 | 39 |
| F03 무거운 상품 | 97.7% | 11 | 1 | 11 |
| F04 마을 거점 | 99.8% | 0 | 1 | 367 |

식료품 제공처(F01 또는 F02 확정) 가게: 키워드 120곳, LLM 120곳 (전체 152곳). 수는 같지만 구성이 다르다.

**LLM이 나았던 경우**
- 운암슈퍼휴게실: 이름의 "휴게실" 때문에 키워드가 제외했지만 LLM은 동네 슈퍼로 판단 (F01 0.8)
- 명성수산: 업종이 슈퍼마켓이라 키워드는 F01 0.9를 줬지만 LLM은 수산물 가게로 판단 (F02 0.9)
- 주유소 안 매장(닛시오일마트주유소): 키워드는 "마트" 때문에 F01·F02·F03 확정, LLM은 제외

**LLM이 의심스러운 경우 (담당자 확인 필요)**
- 추억박물관·천담쉼터·운암산장에 F01 0.7: 관광지 매점일 가능성이 있는데 확정으로 줌
- 마트의 F03을 0.5~0.55로 낮춤: 하나로마트·규모 있는 마트의 쌀·생수 판매를 보수적으로 봄

**정리**
- 키워드 규칙은 업종 분류 오류(슈퍼마켓으로 분류된 수산물 가게, 주유소)를 그대로 따라간다.
- LLM은 이름의 맥락으로 업종 오류를 바로잡지만, 관광지 소규모 매장은 여전히 애매하다.
- 두 방법 모두 판단이 갈리는 66건이 담당자 확인 단계의 우선 검토 대상이 된다.

## 3. 정답 라벨 평가 (sample50, B 라벨링)

정답 양성 수: F01 18 · F02 17 · F03 5 · F04 22

| 방법 | 기준 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|
| 키워드 | 확정(0.6↑) | 0.98 | 0.81 | 0.88 |
| LLM v1 | 확정(0.6↑) | 0.85 | 0.94 | 0.89 |
| LLM v2 | 확정(0.6↑) | 0.89 | 0.77 | 0.83 |
| **LLM v3** | 확정(0.6↑) | **1.00** | 0.82 | **0.90** |
| 키워드 | 확인 포함(0.4↑) | 0.90 | 0.92 | 0.91 |
| LLM v3 | 확인 포함(0.4↑) | 0.72 | 0.97 | 0.83 |

기능별 F1 (확정 기준, v3): F01 키워드 0.94 / LLM 0.80 · F02 0.76 / 0.90 · F03 0.89 / 1.00 · F04 0.93 / 0.95

- LLM v3는 **확정 태그가 틀린 적이 없다(정밀도 1.00)**. 애매하면 "확인 필요"로 내려 담당자에게 넘긴다 → 담당자 확인 단계가 있는 서비스 설계와 맞다.
- F02(신선식품)는 LLM이 크게 낫다 (0.76 → 0.90). 업종 분류만으로는 슈퍼마켓의 신선식품 취급 여부를 알 수 없기 때문.
- **F01에서 LLM이 낮은 이유는 대부분 기준 차이다.** LLM이 "틀린" 6건 중 5건은 v3 프롬프트에 A가 넣은 기준(휴게소 편의점·건어물점은 주민 생필품 구매처로 보지 않음)과 B의 라벨(생필품 구매처로 봄)이 다른 경우다. 모델 오류가 아니라 **기능 정의가 아직 합의되지 않았다**는 뜻이다.

**한계**
- 프롬프트를 같은 50건으로 다듬고 같은 50건으로 평가했으므로 v3 점수는 낙관적이다. 다듬는 데 쓰지 않은 별도 샘플로 다시 평가해야 한다.
- 라벨러가 1명(B)이라 라벨러 간 일치도(카파)를 아직 구하지 못했다.

## 4. A·B 기준 합의 반영 (10/26) → 키워드 규칙 수정 + 프롬프트 v4

| 항목 | 합의 |
|---|---|
| 다이소·천원숍 | 생활용품 → F01 |
| 건어물·젓갈 | 가공식품 → F01 확정, F02 없음 |
| 치즈 판매장 | 유제품 → F02만, F01 없음 |
| 휴게소 안 편의점 | 상품은 팔지만 주민 접근이 어려움 → F01 0.5 (확인 필요) |
| 슈퍼마켓 F02 | 0.5 유지. 공백 계산에서 0.4~0.6은 **"부분 제공"** 으로 따로 센다 |

| 방법 | 확정 정밀도 | 확정 재현율 | 확정 F1 | 확인 포함 F1 |
|---|---|---|---|---|
| 키워드 (합의 반영) | 0.98 | 0.85 | **0.91** | 0.95 |
| LLM v3 | 1.00 | 0.82 | 0.90 | 0.83 |
| LLM v4 | 0.98 | 0.82 | 0.89 | 0.83 |

기능별 F1 (확정, 키워드 / LLM v4): F01 0.97 / 0.85 · F02 0.84 / 0.83 · F03 0.89 / 1.00 · F04 0.93 / 0.95

- 남은 LLM 오답 10건 중 슈퍼마켓 F02 4건은 **합의한 설계대로** 0.5~0.55(부분 제공)라 확정 기준에서 빠진 것이다. 라벨(1)과 합의 기준(확인 필요)이 다른 경우다.
- v4에서 새로 생긴 오류: "지에스25오수IC점"을 휴게소 안 편의점으로 보고 F01 0.5를 줬다 (IC 근처 일반 편의점).
- 전체 실행(v4): 새 호출 470회, 입력 640,823 / 출력 36,899 토큰, 79초. 키워드와 확정 일치율 F01 96.9% · F02 94.6% · F03 97.5% · F04 99.8%.

**해석**
- 키워드 규칙에 이 50건을 보고 합의한 기준을 넣었으므로, 이 50건에서는 키워드가 유리하다. 50건 차이(F1 0.89~0.91)는 몇 건 차이라 우열을 말하기 어렵다.
- LLM의 장점은 규칙에 없는 이름(운암슈퍼휴게실, 명성수산, 주유소 매장)을 맥락으로 판단하는 데 있다 → 규칙을 만들지 않은 **새 표본**에서 비교해야 차이가 드러난다.
- 프롬프트 튜닝은 v4에서 멈춘다. 같은 50건으로 더 고치면 과적합만 커진다.
