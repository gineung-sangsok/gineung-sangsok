# 상속 전후 공백 변화 계산 (#47)

- 날짜: 2026-10-28
- 코드: `track2_recommend/gap.py` (판정·합산), `backend/store.py` (`ClosureStore.gap`, `gap_villages`)
- API: `GET /closures/{id}/gap` — 응답 형식은 계약 `Gap` 그대로
- 입력: 상속안(#45, `track2_recommend/recommend.py`)과 같은 후보·기능 목록. 담당자가 기능을 고치면 공백 계산도 따라 바뀐다

## 영향 마을
기능마다, 폐업 가게가 **가장 가까운 제공처였던 법정리**를 영향 마을로 본다. 가게가 있는 법정리는 항상 포함한다.
거리는 법정리 대표점(`villages_ri.csv`의 center)과 제공처 좌표 사이 직선거리다.

## 마을·기능별 기록
| 필드 | 뜻 |
|---|---|
| `before` | 지금(폐업 전) 제공처 = 폐업 가게, 대표점까지 거리 |
| `after` | 폐업 후 상속안을 반영한 제공처. 상속안 자원이 먼저, 남은 가장 가까운 제공처가 뒤 |
| `after.distance_m` | 상속안 자원과 남은 제공처 중 가까운 쪽 거리. 이동장터는 0 |
| `gap` | 상속안을 반영한 뒤에도 공백인지 |

## 공백 판정 (`docs/contracts/spatial_schema.md` 임시 기준)
- 제공처까지 **1km 초과**면 공백
- 이동장터가 같은 면에 다니면 **부분 해소**(공백 아님). 단 **F02 신선식품**은 판매 품목 확인 전까지 이동장터를 해소로 보지 않는다
- 상속안이 없는 기능은 남은 가장 가까운 제공처로만 판정한다
- 농협 배송(R02)이 상속안인데 1km를 넘으면 공백이고, `note`에 "배송 연계 시 해소 가능"을 적는다

## summary (공백 인구)
- `gap_population_before`: 폐업 후 **상속안이 없을 때** 공백 인구
- `gap_population_after`: **상속안을 반영한 뒤** 공백 인구
- 둘 다 **기능별 공백 인구의 평균**이다. 기능마다 공백인 영향 마을 인구(`total_pop`)를 더하고, 폐업 가게의 기능 수로 나눠 반올림한다
- "기능 하나라도 공백인 마을"로 세지 않은 이유: 일부 기능만 해소되면 숫자가 그대로라 상속 효과가 보이지 않는다 (데모에서 349 → 349)
